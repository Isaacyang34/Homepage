本文件針對使用者關心的核心議題進行深度技術剖析：
1. **為什麼主執行檔 (`Stock_Portfolio_Tracker.exe`) 體積達到 ~39.8 MB？**
2. **底層到底包含了哪些元件？技術上如何再分離？**
3. **針對「核心環境幾乎不更新則打包，常異動的業務分離」之需求，提出最具工程價值的再分離架構建議。**

## 壹、 執行檔 39.8 MB 底層真實數據解剖

在 Windows 環境下，為了實現**「使用者完全免安裝 Python、免配置任何環境、點開即用 (Portable)」**，目前的打包方式採用了微型沙盒技術。

經對編譯二進位依賴鏈 (`PKG-00.toc` 與 `Analysis-00.toc`) 進行底層解剖，整體未壓縮前實為 **83.79 MB**，壓縮後為 **39.8 MB**。其真實體積佔比如下：

```
[ Stock_Portfolio_Tracker.exe 總體積 39.8 MB 解剖 ]
 ├── 1. 矩陣與科學計算引擎 (NumPy / OpenBLAS)  ─── 約 25 MB (佔比 ~45%)  [最大元兇]
 ├── 2. 密碼學與零知識同步 (Cryptography)      ─── 約 15 MB (佔比 ~20%)
 ├── 3. 圖像處理與圖標渲染 (Pillow / PIL)       ─── 約 10 MB (佔比 ~15%)
 ├── 4. Python 核心解譯器與標準庫 (Runtime)     ─── 約 18 MB (佔比 ~18%)
 └── 5. 我們的股票業務代碼 (app_core.pkg)       ─── 僅 0.2 MB (佔比 < 1%)
```

## 貳、 使用者需求的核心理念

> **「把我有可能會異動的分離出來不要放在主程式內；若是核心環境的部分幾乎不會有被更新的時候，那就包在一起。」**

這是一個非常成熟、且完全符合現代軟體工程（Micro-kernel / Host-Plugin Architecture）的設計哲學：

* **穩定基底層 (Stable Substrate)**：Python 直譯器、OpenSSL、SQLite3、Tkinter GUI 引擎。這部分數年都不會變動，**直接捆綁在 EXE 內部，作為永久穩固的底座**。
* **高頻異動層 (High-Churn Layers)**：盤後爬蟲、券商規則、財務計算、UI 視窗排版。這部分經常因證交所改版或功能新增而調整，**必須徹底抽離出主程式**。

---

## 參、 針對「常異動分離、穩固環境捆綁」的具體建議

依照上述原則，目前我們已經成功將 12 大模組分離至 `app_core.pkg` (200 KB)。若要進一步深化「再分離」的靈活性，建議推進以下三個具體架構：

### 建議一：宣告式規則分離（Rules & Configs Externalization）
* **問題**：目前很多容易變動的「商業規則」仍然寫在 Python 代碼中（例如各券商手續費折讓率、證交所 API 網址、市場排行爬蟲標記）。
* **作法**：將這些最常隨外部環境變化的規則，從程式碼抽離為純外部 JSON 檔案：
  1. `config/broker_rules.json`：
     - 使用者可自行編輯或新增券商折讓（如：元大 6 折、國泰 2.8 折、當沖稅率 0.15%），**完全不用改程式碼或重新編譯**。
  2. `config/api_endpoints.json`：
     - 定義證交所 (TWSE)、櫃買中心 (TPEx)、Yahoo Finance 的請求 URL 與格式。若官方更換網址，使用者直接改 JSON 即可熱修復！

---

### 建議二：外掛式擴充機制（Plugin / Script Drop-in）
* **作法**：在使用者目錄下開放一個 `plugins/` (或 `scripts/`) 資料夾。
* **效果**：
  - 未來若要新增「特定券商交割單 Excel 匯入」、「自訂技術指標計算」或「特殊報表匯出」等功能。
  - 不需要重新打包 `app_core.pkg`，只需將一個獨立的 `.py` 檔案丟進 `plugins/` 資料夾，主程式開機時自動動態載入！
  - 真正實現「核心包不動、隨插即用」的模組化擴展。

---

### 建議三：底座瘦身優化（將 39MB 的穩定核心砍半至 18MB）
* **問題**：雖然穩定核心 EXE 幾乎不用更新，但 39.8MB 中有近 **20 MB** 是被 `NumPy` 與 `OpenBLAS` 佔據。而 NumPy 只是因為抓取美股的 `yfinance` 間接拉進來的，我們日常台股日K完全可以用純 Python 處理。
* **作法**：
  - 移除對 `pandas` 與 `numpy` 的依賴，日K與報價改用純 Python 輕量處理。
* **效果**：
  - **這個「永遠不變的穩定核心 EXE」體積可以直接從 39.8 MB 砍半到約 18 ~ 20 MB**。
  - 讓整個軟體在初次下載、隨身碟攜帶時更加輕巧靈活！

## 肆、 理想架構全景藍圖

未來演進之極致分離架構：

```
[ 使用者便攜目錄 ]
 ├── 1. 永久穩定底座 (Zero-Churn)    ─── Stock_Portfolio_Tracker.exe (~18-20MB，瘦身後底座)
 ├── 2. 業務功能模組 (Medium-Churn)  ─── app_core.pkg (200KB，日常功能更新目標)
 ├── 3. 外部動態外掛 (Optional)       ─── plugins/ (自訂指標、Excel 匯入外掛，隨插即用)
 ├── 4. 外部規則設定 (User Editable)  ─── config/ (券商手續費折讓、API 網址，免改代碼)
 └── 5. 個人核心資產 (Data Asset)     ─── portfolio.db (個人交易紀錄，永久隔離保護)
```
