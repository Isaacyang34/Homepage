# 零知識端到端加密 (Zero-Knowledge E2EE) 跨平台架構與威脅建模說明書

本系統實作 **客戶端端到端加密 (Client-Side E2EE)** 與 **無伺服器多租戶 (Serverless Multi-Tenant)** 架構，並嚴格遵循 OWASP 最新密碼學安全指引進行威脅建模。

## 2. 密碼學安全標準 (Cryptographic Standards)

1. **金鑰衍生函式 (Key Derivation)**：
   - 演算法：`PBKDF2-HMAC-SHA256`
   - 疊代次數 (Iterations)：**`600,000 次`**（嚴格遵守 OWASP 2023 最新密碼儲存指引，抗 GPU 離線字典暴力破解）。
   - 雙因子金鑰結構：$\text{Key} = \text{PBKDF2}(\text{MasterPassword} + \text{SecretKey}, \text{Salt}, 600000)$。
   - 鹽值 (Salt)：每次加密由密碼學安全亂數生成器（CSPRNG）隨機生成 16 位元組（128-bit）。
   - 目的：徹底防禦彩虹表與顯卡離線字典暴力窮舉。

2. **對稱式認證加密 (Authenticated Encryption)**：
   - 演算法：`AES-256-GCM`（Galois/Counter Mode）
   - 金鑰長度：256-bit（32 位元組）
   - 初始化向量 (Nonce/IV)：隨機 12 位元組（96-bit）
   - 認證標籤 (Auth Tag)：16 位元組（128-bit），防止資料在傳輸途中被任何人竄改。

3. **零知識保證 (Zero-Knowledge Guarantee)**：
   - 使用者的主密碼**永遠不會傳送至雲端**，亦不儲存在任何伺服器日誌。
   - 雲端資料庫僅存放密文；即使雲端供應商（Google Firebase）或伺服器被整庫脫褲，沒有使用者的專屬密碼，任何人都無法還原出任何股票代碼、股數或資產金額。

## 3. 資料儲存結構與容量試算

### 儲存欄位 (JSON Schema in Cloud)
```json
{
  "version": "1.0",
  "updated_at": "2026-10-06 17:30:00",
  "salt_hex": "a9f4c3...10e",
  "nonce_hex": "b7e21a...48c",
  "tag_hex": "3f901a...65d",
  "ciphertext_b64": "9xF0cK..."
}
```

### 容量與額度分析 (Firebase Spark 免費方案)
- **100 檔股票的資料體積**：
  - 未壓縮明文：約 12 KB
  - GZIP 壓縮 + AES-256-GCM 密文：約 **6 ~ 8 KB**
- **1 GB 免費儲存容量**：
  - $1,048,576 \text{ KB} \div 8 \text{ KB} \approx \mathbf{131,000 \text{ 位使用者}}$
  - 個人或親友數十人使用，僅佔用不到免費額度的 **0.01%**。
- **10 GB 每月免費下載頻寬**：
  - 相當於每月可供手機查詢瀏覽超過 **1,250,000 次**。

## 4. 跨平台網頁功能清單 (Web Client Features)

1. **真・原生解密 (Pure Web Crypto API)**：
   - 100% 使用瀏覽器內建原生 `window.crypto.subtle` API，零第三方不可信外部依賴，杜絕供應鏈攻擊。
2. **多租戶隔離**：
   - 同一個網頁網址，不同人輸入不同帳號與專屬密碼，各自解鎖自己的持股。
3. **頂級現代深色美學**：
   - 現代深色沉浸式介面、即時卡片、持股表格、資產配置權重條、配息統計。
4. **隱私脫敏模式 (Privacy Eye Mode)**：
   - 一鍵切換「隱藏真實金額/股數」，在公共場合或他人面前可安心展示投資比重與報酬率。
5. **安全登出機制**：
   - 點擊「登出」或關閉分頁時，立即覆寫並銷毀記憶體中的明文解密物件。
6. **設備智慧自動分析與自適應形態 (Device-Adaptive Layout)**：
   - **手機行動設備 (Mobile)**：自動辨識螢幕尺寸與觸控特性，自動切換為**「現代金融卡片流模式 (Card Stream)」**，每檔股票為獨立深色卡片，現價大字、紅綠膠囊報酬率、股數均價小卡排列，徹底免去 12 欄橫向滑動的痛苦；搭配底部固定懸浮快捷列，單手操作順暢無比。
   - **觸控平板設備 (Tablet)**：自動切換為雙欄自適應卡片網格，橫豎向自動調適。
   - **桌機大螢幕 (Desktop)**：自動切換為高資訊密度之**「專業數據表格 (Data Table)」**，所有欄位完整展開。
   - **手動切換自由**：頂部提供 `[📱 卡片]` 與 `[ 表格]` 隨選按鈕，使用者亦可隨意切換。

## 5. 真實威脅模型分析與防禦邊界 (Threat Modeling & Countermeasures)

在真實世界的資安攻防中，嚴禁盲信虛幻的「絕對零破口」。本系統針對以下 7 大潛在攻擊面建立客觀防禦邊界：

| 潛在攻擊面 | 攻擊情境與破綻 | 系統強制實作之防禦對策 |
| :--- | :--- | :--- |
| **1. 離線暴力字典破解** | Firebase 密文公開可讀時，攻擊者可將密文下載並透過 GPU 叢集無速限猜密碼。 | 1. PBKDF2 疊代拉升至 **600,000 次**。<br>2. 導入 **128-bit Secret Key** 雙因子熵，使純字典窮舉在數學上徹底失效。 |
| **2. Firebase 權限與覆寫** | 雲端若未設規則，任何人可遍歷列舉所有使用者代號，或惡意覆寫刪除密文。 | 1. 規則強制 `.read: false` 封鎖根目錄遍歷列舉。<br>2. 寫入操作強制驗證獨立 `write_token`。<br>3. 本機 SQLite 為絕對資料真源，隨時可一秒重建雲端。 |
| **3. 回滾重放攻擊 (Rollback)** | AES-GCM 僅驗證內容合法，攻擊者可將數月前舊密文貼回，使前端載入過期數據。 | 1. **強制 AAD 綁定**：將 `userId + version + timestamp` 納入 Tag 認證計算。<br>2. 密文內部封裝單調遞增序號 (Monotonic Sequence)，版本逆行時前端拒絕渲染並告警。 |
| **4. 跨帳號密文搬移** | 攻擊者將 A 的密文複製覆蓋到 B 的儲存路徑。 | AAD 深度綁定 `userId`，跨路徑搬移之密文因 AAD 不匹配，GCM Auth Tag 驗證直接拋出致命例外。 |
| **5. 密文長度側信道洩漏** | 密文體積（如 6 KB vs 30 KB）會洩漏使用者的持股檔數規模。 | 加密前強制進行 **PKCS#7 Padding 至固定塊大小（如 32 KB）**，徹底抹除長度分佈特徵。 |
| **6. Web 前端供應鏈依賴** | 網頁腳本若依賴外部不安全 CDN，腳本遭污染時密碼在鍵入當下即被竊取。 | 1. 網頁堅持 **100% 原生純前端**，零外包 JS 庫。<br>2. 啟用嚴格 Content-Security-Policy (CSP)。 |
| **7. 記憶體殘留邊界認知** | 瀏覽器 JavaScript 垃圾回收 (GC) 與不可變字串無法保證實體記憶體即刻覆寫。 | 登出時代碼主動將所有明文物件與 CryptoKey 設為 `null` 釋放引用，但明確向使用者標示本機終端防毒習慣之重要性。 |
