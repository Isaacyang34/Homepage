# Dynamometer 報表與測試資料生成問題診斷、極簡化架構與改善規範報告

**最新修訂時間**：2026-11-23  
**分析對象**：`測試報告整合/SIMW132N-20-10-12` 與 `測試報告整合/SIMW132M-15-08` 全量實測日誌與報表  
**關聯目標**：電機廠驗收測試報告與規格書之全自動無損填入 (`感應電機電機廠測試報告V1.22.1` / `規格書V1.3`)  
**報告目的**：徹底根治 `Dynamometer` (HMI / ReportManager / TestDuty / TestEquivCircuit) 的檔案冗餘、命名混亂、物理量誤植與審查判退缺陷。

---

## 一、 總覽摘要 (Executive Summary)

在本次將 `SIMW132N-20-10-12` 與 `SIMW132M-15-08` 的實測數據整合至外層驗收報告與規格書的過程中，定位出目前 `Dynamometer` 生成邏輯的三大深層弊端：
1. **檔案極度氾濫與多重備份殘留**：單次馬達測試產生高達 41 個檔案，同一個結果重複寫入 2～3 次，底層採樣檔、中斷重試檔未隔離，造成人類工程師與自動化腳本極易誤判。
2. **等效電路電阻定義與出廠檢驗混淆**：機台介面雖有輸入實測電阻，但混淆了出廠實測「線電阻 ($R_{\text{line}}$)」與等效電路模型「相電阻 ($R_1$)」，導致自動審查公式報出「$R_1$ 與各項電阻平均值 $>3\%$」而判退。
3. **電壓額定寫死為安全低壓**：表頭額定電壓寫死為驅動器降壓值 260V，導致 S1 實測 330V 被算出 $26.923\%$ 巨額誤差判退。

本報告提出**「4 檔極簡化架構 (Single Unified Test Bundle)」**與完整的根治修復方針。

### 2. 定子電阻 $R_1$ 線電阻與相電阻混淆 (審查公式判退 No)
* **現象**：
  驗收報告的「自動審查」頁面中，項次 13 等效電路定子電阻 $R_1$ 顯示 **No**，未通過原因標註：`R1與各項電阻平均值>3%`。
* **致命根因**：
  1. 電機繞組為 **Y 接法**。在物理定義上：
     * **冷態線電阻** ($R_{\text{line}}$)：任兩出線端間之阻抗（出廠標籤實測為 $R_{uv}=0.21, R_{vw}=0.21, R_{uw}=0.21\ \Omega$，平均 $R_{\text{avg}} = 0.21\ \Omega$）。
     * **定子等效相電阻** ($R_1$)：Y 接單相繞組阻抗，物理公式嚴格為：
       $$R_1 = \frac{R_{\text{line\_avg}}}{2} = \frac{0.21}{2} = \mathbf{0.105\ \Omega}$$
  2. 審查判定公式為：
     ```excel
     =_xlfn.IFS(ABS((F7/2 - F177)/F177) <= Q25, "Yes", F177="-", "-", TRUE, "No")
     ```
     其中 $F7$ 是 Step 3 實測線電阻平均值 ($0.21\ \Omega$)，$F177$ 是 Step 13 填入的定子相電阻 $R_1$。
  3. **源頭錯誤**：上位機在等效電路介面上雖然有讓使用者輸入電阻（`numEquivStatorR1`），但操作者輸入的是現場實測的線電阻 `0.21`，軟體卻直接把它當成相電阻 $R_1$ 寫入報表。導致公式計算 $\frac{0.21/2 - 0.21}{0.21} = -50\% > 3\%$，當場被審查系統判退！

### 3. 表頭額定電壓誤植為 260V 降壓設定值 (電壓誤差 26.923% 判退)
* **現象**：
  驗收報告自動審查中，S1 100% 額定轉速操作之「平均電壓誤差(%)」顯示 **`26.923%`**，判定為 **No**（未通過原因：`平均電壓誤差>5%`）。
* **致命根因**：
  1. 審查公式為：`H33 = (AVERAGE(E33:G33) - 電機廠報告與驗收規範!$H$3) / 電機廠報告與驗收規範!$H$3`。
  2. 現場滿載實測線電壓為 $327.4\text{V} \sim 330.0\text{V}$。
  3. 上位機在產表時，表頭額定電壓 `H3` 誤抓了驅動器內部初始安全低壓參數 **260V**（如 `originalUf09Val = 260`），導致算式變成：
     $$\frac{330 - 260}{260} = \mathbf{26.923\%}$$
  4. 該馬達真實額定電壓為 **330V**，表頭 `H3` 必須填入 `330`，實測誤差即為 $0.00\%$ (Yes)。

---

### 4. 項次 15 激磁電流測試結果空白 (-100% 報錯)
* **現象**：
  驗收報告 Step 15「激磁電流測試」，設計值顯示 `16.13 Arms`，但測試結果格空白，誤差顯示 **`-100%`**。
* **致命根因**：
  空載試驗在額定電壓 327.7V 下已精確測出激磁電流 $I_0 = 16.13\text{ Arms}$。上位機產表模組填寫了表頭基準 `N5 = 16.13`，卻**漏寫了 Step 15 的實測儲存格 `L81`**。因 $L81$ 為 0，公式 `(L81-K81)/K81` 直接算出 $-100\%$ 紅字。

---

### 5. 馬達溫升實驗表格缺少冷卻液物性常數 (公式崩潰 #VALUE!)
* **現象**：
  `馬達溫升實驗表格` Row 7 ($B7:E7$) 完全空白，冷卻散熱功率公式 $O15:O17$ 乘數缺項，整欄爆出 `#VALUE!`。
* **致命根因**：
  機台溫升試驗介面已有冷卻模式選單，並在 CSV 輸出 `# CoolingType: Water`。但產表模組沒有將水冷對應之物性常數填入報表：
  * 密度：**0.98** $\text{g/cm}^3$
  * 比熱：**4.184** $\text{J/g}\cdot\text{K}$
  * 黏度：**0.893** $\text{mm}^2/\text{s}$

---

### 6. 機械功率與轉速帶負號
* **現象**：
  動力計在負載吸收發電模式下，編碼器與扭力感測器方向相反，記錄為 `-1500.82 rpm` 與 `-18.56 kW`。
* **致命根因**：
  `Dynamometer_TestDuty.cs` 寫入日誌時未對實測轉速與功率調用 `Math.Abs()`，導致 Excel 審查比對 `實測 - 目標` 算出 `-3000 rpm` 判退。

## 三、 核心檔案生成極簡化架構 (Single Unified Test Bundle)

為徹底解決「檔案多到不知道去哪裡找」與「腳本/人類皆會誤判」的困境，Dynamometer 輸出架構強制實施**「4 檔標準化發布」**：

```
📁 測試報告整合/[MotorModel]/
├── 📄 [MotorModel]_Duty_S1-Rated.csv        ★ S1 額定連續溫升與電氣遙測 (唯一檔)
├── 📄 [MotorModel]_Duty_S2-30min.csv        ★ S2 150% 過載溫升與電氣遙測 (唯一檔)
├── 📄 [MotorModel]_Duty_S6-Cycle.csv        ★ S6 週期過載溫升與電氣遙測 (唯一檔)
├── 📄 [MotorModel]_EquivCircuit_Params.csv  ★ 等效電路與出廠檢驗綜合參數 (唯一檔)
└── 📁 Raw_Archive/                         (所有底層 .gbd、中斷 ABORTED 測試全數移入此處)
```

### 1. 徹底廢除重複寫檔代碼
* **刪除** `File.Copy(path, legacyPath, true)` 與所有 `Report_Duty_*` 舊檔名生成。
* **刪除** `_Latest.csv` 的冗餘複製。每個測項在完成測試時，直接以最新完成時間戳命名並覆寫同名正式檔。
