# 修仙主題像素動作 RPG (Action RPG) 專案 Token 消耗預估報告

本報告針對參考 [action-rpg](https://github.com/arthurazs/action-rpg) 專案架構所規劃之 **MyPixelGame（修仙世界主題）** 進行 Token 消耗預估與分析。

## 專案預期目錄結構
```
MyPixelGame/
├── assets/                  # 美術與音效資源
│   ├── sprites/            # 角色、怪物 Sprite Sheet
│   ├── tilesets/           # 地圖 Tilemap
│   └── audio/              # 8-bit / Chiptune 音效與 BGM
├── src/
│   ├── core/               # 全域核心系統
│   │   ├── GameManager.gd  # 遊戲狀態（Pause, Game Over, Level Switch）
│   │   ├── AudioManager.gd # 音效播放器
│   │   └── EventBus.gd     # 全域事件總線（發佈/訂閱模式）
│   ├── entities/           # 實體物件
│   │   ├── player/         # 玩家（Input, State Machine, Animation）
│   │   └── enemies/        # 敵人 AI
│   ├── level/              # 地圖與關卡邏輯
│   └── ui/                 # 像素風格 UI（血條、選單、對話框）
```

## 🔍 各細項預估細節說明

1. **`src/core/` 核心系統 (約 2 ~ 4 萬 Token)**
   - **`EventBus.gd`**：輕量化事件發佈/訂閱模式，預估消耗約 2,000 ~ 4,000 Token。
   - **`GameManager.gd`**：負責掌管修仙境界（練氣期一重~九重、築基期等）、突破條件判定、存讀檔與遊戲狀態切換，邏輯較多，預估 10,000 ~ 20,000 Token。
   - **`AudioManager.gd`**：音效與 BGM 控制器（包含功法音效、渡劫雷鳴、環境音壓），預估 8,000 ~ 16,000 Token。

2. **`src/entities/player/` 玩家實體與修仙邏輯 (約 4 ~ 8 萬 Token)**
   - 包含角色基本移動與 2D 動畫狀態機。
   - **修仙特化機制**：靈力值 (MP) 消耗、打坐吸納靈氣、御劍/閃避、法術/劍氣攻擊等，邏輯複雜度最高，程式碼量最大。

3. **`src/entities/enemies/` 敵人 AI 系統 (約 3.2 ~ 7 萬 Token)**
   - 基礎妖獸與敵對修仙者的 Behavior Tree / 有限狀態機 (FSM)。
   - 傷害計算（法術傷害/物理傷害、防禦屬性）、死亡後的妖丹與靈石掉落邏輯。

4. **`src/level/` 關卡與環境靈氣 (約 3 ~ 6.2 萬 Token)**
   - 地圖載入、洞府/宗門與野外地圖切換。
   - 靈氣區域（影響玩家打坐恢復速度與修練效率）的 `Area2D` 邏輯。

5. **`src/ui/` 介面與突破介面 (約 4 ~ 8.7 萬 Token)**
   - 像素 UI 設計：血條、靈力條、當前境界標籤。
   - 修仙特色 UI：突破/渡劫介面（機率判定與提示）、背包系統（靈石、丹藥、功法祕笈）與打字機效果對話框。

6. **迭代與 Debug (約 6 ~ 13.5 萬 Token)**
   - 隨專案規模擴大，後續除錯時需要輸入較多關聯檔案的內容作為 Prompt，故會佔用較大的 Input Token。

---

## 💡 降低 Token 消耗的建議
1. **分模組單獨開發**：一次僅專注於一個 `.gd` 檔案或單一功能（如：先寫 `EventBus.gd`，再寫 `GameManager.gd`），避免每次帶入過多不相關的代碼上下文。
2. **定義明確的 Data Schema**：在開發實體前，先鎖定修仙數值架構（如：境界列表、靈力公式），減少重複修改引起的 Token 浪費。
