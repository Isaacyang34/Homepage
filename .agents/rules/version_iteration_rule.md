# 版本迭代與更新觸發最高規範 (Version Iteration & Release Trigger Rule)

## 1. 核心原則 (Core Philosophy)
* **純外觀/ICON 修改不更動版本號**：
  * 若僅是更換圖標 (Icon)、微調配色 (Color Mode)、修正按鈕形狀/邊框或修飾文字排版等外觀層級微調，**嚴格禁止更動版本號**，保持原版本。
* **新增功能或頁面/分頁時更新第三位版本號**：
  * 當系統有實質的**「新增功能」**、**「新增獨立視窗/頁面 (Dialog / Window)」**、或**「新增功能分頁 (Tab)」**時，推進第三位版本號（例如 `V1.0.1` -> `V1.0.2`）。
* **小幅度改版 / Bug 修正 / 效能調優往下延伸第四位版次**：
  * 若為局部邏輯修復、Bug Hotfix 或效能調優（例如盤後資料修正、連線重試、狀態防呆解鎖等），**在第三位之後往下更新第四位版次號碼**（例如 `V1.0.2` -> `V1.0.2.1` -> `V1.0.2.2`）。

## 2. 語意化版本號結構 (Semantic Versioning Standard)
* 版本格式採階梯式語意化結構：`V<Major>.<Minor>.<Feature>[.<Patch_Fix>]`
  - 重大架構/功能里程碑：`V1.0.1`, `V1.0.2`
  - 小幅修正與微調：`V1.0.2.1`, `V1.0.2.2`
* 嚴禁跳過位元（例如嚴禁從 `V1.0.1` 逕行跳至 `V1.1`）。
* 版本比對函式 `parse_version_tuple` 必須自動補齊至 4 位 tuple 進行精準階梯比對。
