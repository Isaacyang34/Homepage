# 單檔原子化整合同動修改鐵律 (Single-Pass Atomic Edit Rule)

## 核心精神：嚴禁零碎拖沓分段修訂，杜絕碎步操作

### 1. 觸碰檔案前之全局規劃原則
- 凡涉及同一檔案內多處修改（包含成員變數宣告、UI版面建立、事件監聽、資料解析與輔助函式）：
  - **嚴格禁止**「查一次檔案、改幾行、再查一次、又改幾行」的零碎操作！
  - 必須在動手前先通盤掌握各區塊之行號、上下文與依賴關係。

### 2. 單次原子化提交 (Atomic Execution)
- 對於同檔案的多處變更，**強制使用一次性批量編輯工具一次改完**。
- 確保每一次對目標檔案的寫入都是完整、具備語意連貫性、且改完後能直接編譯通過。

### 3. 零藉口、零說詞
- 不得以「區塊分開」或「邊看邊改」為由推託分段操作。
- 凡違反此鐵律進行碎步修改者，視同重大操作紀律缺失。
